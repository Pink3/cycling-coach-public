# 微信推送格式规范（PushPlus）

> 本项目所有微信推送（PushPlus）统一按本文档排版，保证手机端阅读整齐、结构一致。
> 推送脚本：`scripts/push_pushplus.py`（token 存 `~/.config/cycling_coach/pushplus_token`，权限 600，脚本自动读取）。

## 1. 通用规则

- 模板类型固定 `html`（脚本默认），微信渲染最稳定；禁止使用 Markdown 裸换行（微信不渲染 `\n`）。
- 排版符号：换行 `<br>`；加粗 `<b>…</b>`；数值分隔 `｜`；列表项 `•`。
- 数值缺失一律标 `—`（如压力值未同步时）。
- 标题带日期：`标题（YYYY-MM-DD）`。

## 2. 今日状态块（所有推送必带）

两条推送都必须在正文开头附「📊 今日状态」块，数据来自 `fetch_icu.py --days 2` 的 wellness 字段：

```html
<b>📊 今日状态</b><br>
睡眠 Xh ｜ HRV X ｜ 静息心率 X ｜ 压力 X<br>
CTL X ｜ ATL X ｜ TSB X（状态解读）｜ 体重 Xkg
```

- 第 1 行：恢复信号（睡眠 / HRV / 静息心率 / 压力）
- 第 2 行：训练负荷（CTL 适应度 / ATL 疲劳 / TSB 状态 / 体重）
- TSB 状态解读参照 SKILL.md 的 TSB 区间表（如"最佳训练区 / 过度训练区 / 高风险"）。

## 3. 18:00 主报告（完整报告格式）

标题：`📋 每日骑行训练分析（YYYY-MM-DD · 18:00）`

正文三段式，与豆包内完整报告结构一致：

```html
<b>一、当天状态摘要</b><br>
最近训练：类型 时长min ｜ IF X ｜ 负荷 X<br>
昨天：休息/训练描述<br>
睡眠 Xh ｜ HRV X ｜ 静息心率 X ｜ 压力 X<br>
TSB <b>X</b>（状态解读）｜ CTL X ｜ ATL X<br>
<br>
<b>二、今晚训练计划</b><br>
训练类型 + 目标区间（%FTP 或心率）<br>
• 热身 Xm → 主项… → 冷身 Xm<br>
• 总时长约 Xmin<br>
• 开练时间：X 点开骑，X 点前收车<br>
• 安全阀/关键决策一句<br>
<br>
<b>三、决策理由</b><br>
1. 规则命中点（TSB 区间 / 睡眠 / 前一天状态）<br>
2. 为什么这样安排<br>
3. 力量训练是否启动及原因<br>
<br>
<b>🍚 补给</b><br>
练前… ｜ 练后… ｜ 一句提醒<br>
明日：XX
```

## 4. 简版提醒（17:00 同步 / 21:00 打卡）

同样带「📊 今日状态」块，提醒部分保持简短：

- **17:00 同步提醒**：`<b>⏰ 提醒</b><br>今晚 18:00 训练分析前，请把手表/码表的睡眠、HRV、活动数据同步到 Intervals.icu。`
- **21:00 打卡提醒**：`<b>🍽️ 打卡提醒</b><br>请回复：早餐/午餐/晚餐/加餐/水分，教练将评估并给次日建议。`

## 5. 手动测试

```bash
python3 scripts/push_pushplus.py "测试（日期）" --content "<b>📊 今日状态</b><br>…"
```
